Architecture

Barista is a native macOS menu bar app built with AppKit and Swift Package Manager. Zero third-party dependencies. Every widget is a standalone Swift file conforming to the BaristaWidget protocol.

Project structure

Barista/ 
Core/
  BaristaWidget.swift       // widget protocol + registry
  AnyBaristaWidget.swift    // type-erased wrapper
  WidgetInstance.swift       // status item lifecycle
  StatusBarController.swift  // manages all instances
  DataFetcher.swift          // HTTPS-only network layer
  MenuBarManager.swift       // hide/show/reorder
  ProfileManager.swift       // named widget profiles

Widgets/
  Finance/       // StockTicker, Crypto, Forex
  System/        // CPU, Memory, Disk, Network, GPU, Temp
  Weather/       // Weather, AirQuality, UVIndex
  Productivity/  // Pomodoro, FocusTask, Meeting, Clipboard
  Sports/        // LiveScores, F1, Soccer
  Developer/     // Docker, GitHub, ServerPing
  ...            // 12 categories total

App/
  AppDelegate.swift          // settings window + gallery

Data flow

Each widget runs independently. On start(), it fetches data (API, shell, local), updates internal state, and calls onDisplayUpdate?(). The WidgetInstance calls render() to get a WidgetDisplayMode and applies it to the NSStatusItem button. Dropdowns are built lazily via buildDropdownMenu().

Creating a Widget

Every widget needs a config struct, a class conforming to BaristaWidget, and registration in the widget registry. Three steps.

  1. Define the config

    A Codable struct that holds user-configurable values. Must have a static default.

    MyWidget.swift 
    struct MyWidgetConfig: Codable, Equatable {
    var refreshRate: Int
    static let `default` = MyWidgetConfig(refreshRate: 60)
}

  2. Implement the widget

    Conform to BaristaWidget with all required static properties and instance methods.

    MyWidget.swift 
    class MyWidget: BaristaWidget {
    static let widgetID = "my-widget"
    static let displayName = "My Widget"
    static let subtitle = "Does something cool"
    static let iconName = "star"         // SF Symbol
    static let category = WidgetCategory.utility
    static let allowsMultiple = false
    static let isPremium = false
    static let defaultConfig = MyWidgetConfig.default

    var config: MyWidgetConfig
    var onDisplayUpdate: (() -> Void)?

    required init(config: MyWidgetConfig) {
        self.config = config
    }

    func start() { /* begin fetching data */ }
    func stop()  { /* invalidate timers */ }

    func render() -> WidgetDisplayMode {
        return .text("Hello")
    }

    func buildDropdownMenu() -> NSMenu {
        let menu = NSMenu()
        // add items...
        return menu
    }

    func buildConfigControls(
        onChange: @escaping () -> Void
    ) -> [NSView] {
        return []
    }
}

  3. Register it

    One line in BaristaWidget.swift:

    BaristaWidget.swift 
    WidgetRegistry.register(MyWidget.self)
Tip: Set allowsMultiple = true if users should be able to add multiple instances with different configs (e.g., multiple stock tickers tracking different symbols).

Display Modes

The render() method returns a WidgetDisplayMode that controls how the widget appears in the menu bar.

ModeUsageExample
.text(String)Plain text label.text("72F")
.attributedText(NSAttributedString)Colored or styled textGreen text for live scores
.icon(NSImage)Template imageCoffee cup, moon icon
.iconAndText(NSImage, String)Image with labelBattery icon + percentage
.scrollingText(NSAttributedString, width:)Marquee for long contentNews headlines, long tickers

Protocols

Optional protocols add capabilities to your widget.

Cycleable

Widgets that cycle through multiple items (e.g., Live Scores cycling through games).

Protocol 
protocol Cycleable {
    var itemCount: Int { get }
    var currentIndex: Int { get }
    var cycleInterval: TimeInterval { get }
    func cycleNext()
}

InteractiveDropdown

Widgets that show a rich popover instead of a plain NSMenu.

Protocol 
protocol InteractiveDropdown {
    func buildPopoverContent() -> NSView
    var popoverSize: NSSize { get }
}

xbar Script Compatibility

Barista's Script Widget runs xbar/SwiftBar-compatible scripts. Write a shell script, set it as the script path, and Barista parses the output.

Output format

my-script.5m.sh 
#!/bin/bash
echo "Menu Bar Text"
echo "---"
echo "Dropdown Item 1 | color=green"
echo "Dropdown Item 2 | href=https://example.com"
echo "--Submenu Item | color=#aaa"

Pipe parameters

ParameterDescriptionExample
colorText color (name or hex)color=#ff6600
hrefURL to open on clickhref=https://example.com
bashShell command on clickbash=/usr/local/bin/script
sfimageSF Symbol iconsfimage=star.fill
sizeFont size in pointssize=14
fontFont family namefont=Menlo
Security: Shell paths are validated against a whitelist. Only /bin/sh, /bin/bash, /bin/zsh, and their /usr/local and /opt/homebrew variants are allowed. Scripts in system directories are blocked.

Building from Source

Requirements

  • macOS 13 Ventura or later
  • Xcode 15+ (or Swift 5.9+ toolchain)
  • No third-party dependencies required

Clone and build

Terminal 
git clone https://github.com/noamsmall18/barista.git
cd barista
swift build

Release build

Terminal 
# Optimized binary
swift build -c release

# Package as .app
mkdir -p dist/Barista.app/Contents/MacOS
cp .build/release/Barista dist/Barista.app/Contents/MacOS/
cp Barista/Info.plist dist/Barista.app/Contents/

# Codesign
codesign --force --sign - \
  --entitlements Barista/Barista.entitlements \
  dist/Barista.app

Run

Terminal 
open dist/Barista.app

Security

Barista is hardened against common attack vectors. All network requests, script execution, and user input are validated.

LayerProtection
NetworkHTTPS-only enforcement in DataFetcher. All URL parameters percent-encoded.
ScriptsShell whitelist (6 allowed paths). System directory execution blocked. File permission checks.
InputHost sanitization on ServerPing. Symbol encoding on Finance widgets. Path traversal prevention.
xbarhref restricted to http/https schemes. AppleScript bash handler sanitized.
SandboxApp Sandbox entitlement with minimal permissions. Outgoing network + file read only.
Reporting vulnerabilities: If you find a security issue, please open a GitHub issue or contact the maintainer directly. We take security seriously and will patch critical issues within 24 hours.
